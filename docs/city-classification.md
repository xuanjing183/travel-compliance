# 城市分级与备用酒店库覆盖标准

本文档约定可信本地酒店目录（`tests/fixtures/providers/hotels.json`）的城市覆盖策略。
目录是唯一的可信定价来源（HC-03）；Tavily 网络参考永远不生成分级、价格或候选。

## 城市分级标准

### A 类城市（一线城市）

北京、上海、广州、深圳

### B 类城市（新一线/二线）

杭州、南京、成都、武汉、西安、重庆、苏州、天津、郑州、长沙、青岛、大连

### C 类城市（其他常见出差目的地）

洛阳、开封、珠海、佛山、东莞、无锡、宁波、厦门、福州、昆明、贵阳、南宁、太原、石家庄、济南、合肥、南昌、兰州、乌鲁木齐、呼和浩特、哈尔滨、长春、沈阳

> 制度内的报销上限以已发布制度（RuleSet）为准，本文分级仅决定目录覆盖密度，
> 与 `RuleSet.tier_of()` 的兜底口径（未列城市按 C 类）保持一致。

## 备用酒店库覆盖策略

- A 类城市：至少 3 家协议酒店 + 2 家备用酒店
- B 类城市：至少 2 家协议酒店 + 2 家备用酒店
- C 类城市：至少 1 家协议酒店 + 1 家备用酒店

目录未覆盖的城市仍按契约降级：无候选 → 待人工补录，
并按"适用住宿报销上限 × 晚数"展示非报价预算参考（D-18）。

## 价格参考

备用酒店价格基于市场调研设定：

- A 类城市：协议酒店价格的 90–110%
- B 类城市：协议酒店价格的 85–105%
- C 类城市：协议酒店价格的 80–100%

允许个别条目故意高于员工上限（如洛阳 `H-LUO-BACKUP-01/02`），
用于覆盖"超标最少的例外"（`HOTEL_OVER_CAP`）路径；该例外必须可见、可追溯，不参与自动审批。

## 维护流程

### 当前覆盖城市

- A 类：上海（协议 ×2）
- B 类：成都（备用 ×1）
- C 类：洛阳（备用 ×2）、开封（备用 ×1）、郑州（备用 ×1）

### 添加新城市

1. 在 `tests/fixtures/providers/hotels.json` 中添加酒店条目（`source: "backup_fixture"`、`kind: "backup"`）。
2. 价格符合上文分级标准，并注明 `distance_note` 与 `valid_until`。
3. 更新本文档"当前覆盖城市"。
4. 在 `tests/test_planning.py::test_backup_catalog_covers_common_business_cities` 中登记该城市。
5. 运行全量回归验证。

### 价格更新

备用酒店价格每半年审核一次，确保：不超过制度规定的城市上限（故意保留的超标样本除外）、
反映市场实际情况、在 Demo 场景中合理。修订时同步更新 `valid_until`。
