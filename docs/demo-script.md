## 1. 3 分钟脚本（HR / 业务价值）

**主线：一句话发起 → 系统算清成本与合规 → 该自动的自动、该人审的人审 → 全程可追溯。**

| 时间 | 操作 | 讲什么（台词要点） |
|---:|---|---|
| 0:00–0:20 | 停在身份选择页 | 「中小企业把差旅制度放在 Word/PDF 里：员工靠翻、审批靠经验、财务到报销才发现超标。这个项目把制度**编译成可执行的规则**，在**花钱之前**就算清成本、标出例外。」 |
| 0:20–0:30 | 选 **张三**，进「我的申请」 | 「员工视角。不用翻制度，直接说人话。」 |
| 0:30–1:00 | 点「新建申请」，输入框输入：**下周去上海参加供应商大会，预算四千** → 点「开始」 | 「系统从一句话里抽取出目的地、事由、预算，**只追问缺失的**出发地、起止日期——注意它**不会**把『下周』瞎猜成具体日期。」按提示在对话框补全：从北京出发、10-28 到 10-30 → 点「发送」。 |
| 1:00–1:30 | 槽位齐后点 **提交校验**，等方案出来 | 「提交瞬间，系统按**已确认的制度规则**规划：选交通和酒店候选、算出总额 **4760 元**（整数分计算，不用浮点）、给出判断——**违规 0 项、审批理由 2 项**（超申报预算、超自动通过阈值）。这一单超了自动审批阈值，所以**生成审批卡**交给人。」 |
| 1:30–2:00 | 打开方案/审批卡，指成本拆解、违规、**来源徽标**、条款引用 | 「关键在这：每个数字都能**追溯**——交通/酒店/天气/摘要各带来源徽标，违规挂着**具体条款引用**。审批人拿到的不是『我觉得超标』，而是算好的证据。」 |
| 2:00–2:30 | 切 **李四** →「待我审批」→ 打开这张卡 → **批准**（填意见）→ 状态变 `DELIVERED` | 「直属经理审批。批准后立即交付，邮件进**本地 Outbox**——这是演示终点，不连真实订票/支付/邮件。」 |
| 2:30–3:00 | 切 **王五** →「运维」看 Outbox / 审计时间线 | 「全程留痕：从输入、条款、规则、供应商数据到审批、交付，一条**不可篡改的审计链**。制度改版还能对存量申请**重新校验**。这就是『先知道是否合规，再决定怎么走』。」 |

**收尾一句话**：「合规判断从『报销后追讨』前移到『规划阶段拦截』，口径统一、全链路可审计。」

## 2. 10 分钟脚本（技术面深挖）

**主线：确定性核心 → 模型边界（fake/recorded/real）→ 网络与费用守卫 → RAG 引用终审 →
故障降级 → 持久化恢复 → 制度编译 → 评测证据。**

| 时间 | 主题 | 操作 / 证据 | 讲什么 |
|---:|---|---|---|
| 0:00–1:00 | 架构与确定性 | 打开 [architecture.md](architecture.md)；`uv run pytest -q` 展示全绿 | 「分层：domain（规则/金额/状态机，纯函数）→ planning（Provider+选择器）→ workflow（LangGraph+checkpoint）→ api（FastAPI+SSE）→ static（原生 ES module SPA，无构建）。金额一律整数『分』（HC-02），规则结果**从不** fake。」 |
| 1:00–2:00 | 三种 LLM 模式 | 打开 [integration.md](integration.md) §1；指 `main.py` 的 `build_*` | 「fake/recorded/real **接口签名一致**，业务代码不感知模式。fake 零网络确定性；recorded 按输入 SHA-256 回放；real 才调 DashScope。D-08：质量指标**只能**用 real 算。」 |
| 2:00–3:00 | 出站网络边界 | `GET /api/health/providers` 看 `network`；打开 AC-021 证据 | 「守卫在 lifespan 全程安装，拦截 getaddrinfo/create_connection/connect/urlopen 四条途径。允许清单**由配置推导、无运维开关**：fake 空集、real 仅 dashscope。非清单主机在 DNS 离开机器前拒绝并记 jsonl。这是纵深防御不是沙箱——挡不住子进程/C 扩展。」 |
| 3:00–4:00 | 费用守卫 | 打开 `artifacts/cost-ledger.md`、`llm-usage.jsonl` | 「每次真实调用前查累计、调用后记账。spent = 台账手工行 + JSONL 运行期；≥40 元抛 `BudgetPaused` 拒绝调用，台账不可读也拒绝（fail closed）。密钥只读环境名、从不打印（F-03/HC-07）。累计约 2.49 元 / 50 元。」 |
| 4:00–5:30 | 黄金路径 + 规则计算 | 现场跑 S-01（同 3 分钟脚本 0:30–2:00） | 「重点看规划：城市档位→住宿/补贴上限、舱位、提前期、自动审批阈值都是**已确认规则**在算。S-01 总额 476000 分、识别 `BUDGET_EXCEEDED`+`OVER_AUTO_APPROVAL_LIMIT` 进审批；S-02 合规低于阈值则 `AUTO_APPROVED`。」 |
| 5:30–6:30 | 故障降级（S-09） | 运维页开 `transport_timeout` 故障 → 跑 S-02 同输入 | 「交通 Provider 超时**不崩溃**：交通标『待人工补录』，`total_fen=null` 但给 `known_subtotal_fen`，审批理由含 `PLAN_INCOMPLETE`，进 `PENDING_APPROVAL`（对照 S-02 本应自动通过）。**绝不把缺失按 0 计入**而误判。Provider 响应任一条目 Schema 不合格→整份作废（IMP-24）。」 |

| 7:30–8:30 | 制度编译（S-12） | 王五「制度管理」：上传 v1.3 → 抽取 → 逐条确认（看引用定位）→ 发布 → 回张三详情「按新版本重新校验」 | 「模型抽取的规则是**候选**，必须管理员逐条确认（含引用定位）才发布；ID 由代码按类型+顺序分配，不信模型给的 ID（IMP-66）。重新校验后 revision+1、绑定 v1.3、旧审批失效，480/晚超新上限 450 新增违规，审计保留 v1.2 与 v1.3 两次结果。」 |
| 8:30–9:30 | RAG 引用终审 | 制度问答页问一条有答案 + 一条无答案的；打开 AC-004/017 证据 | 「制度按条款下连续段落切块，引用即块文本、定位逐字匹配（不模糊、找不到即 `invalid_quote`）。**代码终审引用**：只认模型看过的块 ID，无有效引用的『可回答』降级为拒答、拒答引用清空。real 模式实测引用命中 20/20、数值 11/11、拒答 5/5。vector 与 hybrid Recall@3 打平→按 D-17 保留纯向量。」 |
| 9:30–10:00 | 评测与验收 | 打开 [acceptance.md](acceptance.md)、[TASK-011 证据索引](../artifacts/acceptance/TASK-011/README.md) | 「门控项（AC-004/017/018/025/029）用真实模型验收并达阈值；确定性场景 36/36；耗时中位数 4.2s。数据集冻结+SHA-256，脚本可复现。已知限制如实区分：未验证/外部阻塞（AUTH-02 Live Provider）/降级/已通过。」 |

**深挖备问（评委可能追问）**：

- *为什么不用浮点算钱？* → 整数分存储与计算（HC-02），显示时换算元，避免累计误差。
- *模型乱写金额怎么办？* → 摘要含金额/超 400 字/为空即丢弃标 unavailable，金额只来自代码（IMP-31）。
- *怎么证明不是回放？* → AC-029 真实视觉输出与录制 fixture 措辞不同而语义一致。
- *审批被抢跑/重复决策？* → 同 Trip 提交运行与决定共用进程内锁；已处理 revision 再决策返回 409（IMP-30/33）。
- *制度问答会泄露草稿吗？* → draft 仅 admin 可问，员工只看 published/confirmed（IMP-72/83）。
